# Apex Building Group

Сайт компании по ремонту в Валенсии. Русский, испанский и английский. Готовый HTML, локальные шрифты и WebP; никаких production-зависимостей.

## Локальный запуск

Нужен Node.js 22 или новее. Установка npm-пакетов не нужна.

```sh
node scripts/serve.mjs
```

Открыть http://localhost:4173/. Изменения в `src`, `content` и `public` пересобираются автоматически; обновите страницу браузера.

```sh
node scripts/build.mjs
node scripts/check.mjs
```

Результат в `dist/`. Для production задайте `SITE_URL` равным публичному адресу сайта. Значение влияет на ссылки, canonical, hreflang, sitemap и OG-изображения.

## Редактирование

- `content/ru.mjs`, `es.mjs`, `en.mjs`: все видимые тексты, услуги, 10 этапов, FAQ и форма.
- `content/site.mjs`: название, контакты, реальные проекты и специалисты. Формат добавления приведён в комментариях.
- `public/assets`: фотографии и логотип. Добавьте сюда реальные фото и укажите имена файлов в `projects` / `specialists`. Эти разделы автоматически появляются, когда массивы заполнены.
- `src/template.mjs`: разметка и SEO; `src/styles.css`: оформление; `src/main.js`: меню и форма.

Стоковые интерьеры подписаны как иллюстрации. Сайт не утверждает, что они являются работами компании. Никаких выдуманных отзывов, адресов, стажа или сотрудников.

Бинарные изображения и шрифты в GitHub хранятся в `assets/packed.json` и автоматически восстанавливаются при сборке. Это позволяет передавать их через текстовый GitHub-коннектор. После добавления или замены локальных изображений выполните `node scripts/pack-assets.mjs` и закоммитьте обновлённый файл. Если локальный оригинал есть в `public/`, сборка предпочитает его упакованной копии. В опубликованном сайте находятся обычные WebP/JPG/WOFF2; упаковка не влияет на скорость загрузки.

## Заявки

Форма готовит WhatsApp-сообщение с именем, телефоном, типом помещения и описанием. Клиент отправляет его сам. После подготовки доступны повторное открытие WhatsApp и email. Сайт не сохраняет данные формы. Без JavaScript остаются прямые контакты, а отправка формы отключена.

## GitHub Pages

В репозитории: Settings → Pages → Source → GitHub Actions. Workflow `.github/workflows/pages.yml` собирает, проверяет и публикует сайт после изменений в `main`. Адрес берётся из `actions/configure-pages`, поэтому ссылки работают и под путём `/apex-building-group/`.

## Домен и продвижение

Домен ещё не куплен и не подключён. После покупки `apexbuildinggroup.es` или другого домена добавьте его в Settings → Pages → Custom domain, настройте DNS по инструкции GitHub и включите HTTPS. Перезапустите workflow: SEO-адреса будут собраны для нового домена. Не создавайте CNAME до подтверждения домена.

После подключения домена зарегистрируйте сайт в Google Search Console и отправьте `sitemap.xml`. Для локального поиска добавьте подтверждённый профиль компании в Google Business Profile. При появлении юридического адреса и регистрационных данных дополните уведомление о данных и разметку. Разметка сейчас использует Organization и Service; почтовый адрес и оценки не выдуманы. На проектном URL GitHub Pages robots.txt находится в подкаталоге и не заменяет robots.txt домена `github.io`; sitemap можно передать в Search Console напрямую.

## Источники

Исходные тексты, логотипы и палитра предоставлены заказчиком и исключены из Git. Источники фотографий и лицензия шрифта: [docs/assets.md](docs/assets.md), `public/fonts/OFL.txt`.

SEO обеспечивает техническую доступность и корректные сигналы; позиции в поиске требуют реальных проектов, отзывов клиентов, локального профиля и дальнейшей работы с контентом.
